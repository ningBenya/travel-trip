# ทริปของฉัน

เว็บสำหรับจัดทริปเที่ยวและเก็บค่าใช้จ่าย สร้างได้หลายทริป แต่ละทริปใส่รายการได้ 5 หมวด คือ การเดินทาง ที่พัก ที่เที่ยว อาหาร และช้อปปิ้ง
แต่ละรายการใส่ราคา × จำนวน วันที่ หมายเหตุ ลิงก์ Google Maps และรูปได้หลายรูป (กดขยายดูได้)
มีหน้า **แผนรายวัน** (Day 1, Day 2, …) จากวันไป–วันกลับของทริป แต่ละจุดแวะใส่เวลา การเดินทางมาจุดนั้น ที่อยู่ เวลาเปิด/เช็กอิน เบอร์โทร ได้
แต่ละวันมีคำโปรย เคล็ดลับ ภาพรวมเส้นทาง และปุ่มเปิดเส้นทางทั้งวันใน Google Maps (รายการกับจุดแวะคือข้อมูลชุดเดียวกัน ค่าใช้จ่ายจึงรวมให้เอง)
บันทึกแผนแต่ละวัน (หรือทุกวัน) เป็นรูป PNG แบบอินโฟกราฟิกได้ บนมือถือจะเปิดเมนูแชร์ให้บันทึกลงคลังรูปหรือส่ง LINE ได้เลย
แต่ละทริปตั้งสีพื้นหลังและรูปปกได้ หน้าสรุปจะคำนวณยอดรวม เฉลี่ยต่อคน เฉลี่ยต่อวัน และสัดส่วนแต่ละหมวดให้

ต้องเข้าสู่ระบบก่อนใช้งาน หน้าแรกเป็น **ปฏิทินทริป** ที่แสดงช่วงวันไป–วันกลับของแต่ละทริป
แต่ละคนเห็นและแก้ได้เฉพาะทริปที่ตัวเองเป็นสมาชิก เจ้าของทริปเพิ่มหรือเอาคนออกได้จากปุ่ม "สมาชิก" บนหัวทริป
ผู้ดูแลระบบ (`hwangning`) เห็นทุกทริป และสร้างหรือปิดบัญชีผู้ใช้ได้ในหน้า "จัดการผู้ใช้"
ทุกคนเปลี่ยนรหัสผ่านของตัวเองได้ในหน้า "เปลี่ยนรหัสผ่าน"
ปฏิทินแสดง **วันหยุดราชการ** ด้วย รายการตั้งต้นอยู่ใน `holidays.js` (ปี 2569–2570)
ถ้า ครม. ประกาศวันหยุดพิเศษเพิ่ม หรือวันไหนผิด ผู้ดูแลกด "แก้ไขวันหยุด" ใต้ปฏิทินเพื่อเพิ่ม แก้ชื่อ หรือซ่อนได้เลย ไม่ต้องแก้ไฟล์

ถ้าตั้งค่า Firebase ไว้ ข้อมูลจะเก็บบนคลาวด์และเปิดจากเครื่องไหนก็เห็นเหมือนกัน
ถ้ายังไม่ตั้งค่า ข้อมูลจะเก็บไว้ในเบราว์เซอร์เครื่องที่เปิดเท่านั้น (โหมดนี้ไม่มีการเข้าสู่ระบบ)

## ไฟล์
- `index.html` โครงหน้าเว็บ
- `styles.css` หน้าตา
- `app.js` การทำงานทั้งหมด (หมวดหมู่อยู่ที่ `CATS`, สีพื้นหลังทริปอยู่ที่ `THEMES`)
- `holidays.js` วันหยุดราชการตั้งต้นของแต่ละปี (ขึ้นปีใหม่ค่อยเพิ่มในไฟล์ หรือให้ผู้ดูแลเพิ่มในเว็บ)
- `core.js` ฟังก์ชันที่ไม่ยุ่งกับหน้าเว็บ (username, ข้อความ error, คำนวณปฏิทิน) มี test ใน `tests/`
- `lib/html-to-image.js` ไลบรารีสำหรับแปลงแผนเป็นรูป (MIT)
- `ai-config.js` URL ของตัวกลาง AI (Cloudflare Worker) · เว้นว่าง = ใช้โหมดคัดลอกคำสั่ง
- `ai-worker/worker.js` โค้ดตัวกลาง AI สำหรับวางใน Cloudflare Workers (ไม่ได้ทำงานบน GitHub Pages)
- `firebase-config.js` ค่าตั้งค่า Firebase
- `database.rules.json` กฎของฐานข้อมูล: ใครเห็นและแก้อะไรได้ (คัดลอกไปวางใน Firebase Console)
- `tests/` test ของ `core.js` และของกฎฐานข้อมูล (ไม่ได้ใช้บนเว็บจริง)

## ตั้งค่า Firebase (ทำครั้งเดียว)
1. ไปที่ https://console.firebase.google.com → Add project
2. เมนู Build → Realtime Database → Create Database → เลือก Singapore (asia-southeast1) → Start in locked mode
3. แท็บ Rules → วางเนื้อหาจาก `database.rules.json` → Publish
4. Project settings (รูปเฟือง) → Your apps → กดไอคอน `</>` เพิ่ม Web app → คัดลอก firebaseConfig มาวางใน `firebase-config.js`
5. commit + push แล้วเปิดหน้าเว็บ จะเห็นจุดเขียว "ซิงก์อยู่"

## ตั้งค่าการเข้าสู่ระบบ (ทำครั้งเดียว)
username ที่ใช้ในเว็บจะถูกแปลงเป็นอีเมลภายใน `<username>@travel.local` (ไม่ได้ส่งอีเมลจริง)

1. Firebase Console → **Authentication** → Get started → แท็บ **Sign-in method** → เปิด **Email/Password** → Save
2. Authentication → แท็บ **Users** → **Add user**
   - Email: `hwangning@travel.local`
   - Password: ตั้งเอง (อย่าเขียนรหัสลงในไฟล์ใด ๆ ใน repo นี้)
3. merge โค้ดเวอร์ชันนี้ขึ้น GitHub Pages ให้เรียบร้อย **แล้วค่อย**ไปที่ Realtime Database → แท็บ **Rules** → วางเนื้อหาจาก `database.rules.json` → **Publish**
   (ถ้า publish กฎก่อน เว็บเวอร์ชันเก่าจะใช้งานไม่ได้ทันที)
4. เปิดเว็บแล้วเข้าสู่ระบบด้วย `hwangning` ครั้งแรก ระบบจะสร้างโปรไฟล์ผู้ดูแล และย้ายทริปเดิมทั้งหมดมาเป็นของผู้ดูแลให้เอง
5. ไปที่ "จัดการผู้ใช้" สร้างบัญชีให้คนอื่น แล้วเปิดแต่ละทริป → ปุ่ม "สมาชิก" → เพิ่มคนเข้าทริป

### ลืมรหัสผ่าน
ระบบส่งอีเมลรีเซ็ตรหัสไม่ได้ (อีเมล `@travel.local` ไม่มีอยู่จริง) ให้ผู้ดูแลทำแบบนี้แทน:
1. Firebase Console → Authentication → Users → ลบบัญชี `<username>@travel.local` ของคนนั้น
2. ในเว็บ: "จัดการผู้ใช้" → สร้างผู้ใช้ด้วย username เดิม → กด **แทนบัญชีเดิม** บัญชีใหม่จะได้ทริปเดิมทั้งหมด

ปุ่ม "ปิดบัญชี" ในเว็บตัดสิทธิ์ได้ทันที แต่บัญชีใน Firebase ยังอยู่ ลบได้ที่ Firebase Console

**ห้ามลบบัญชี `hwangning@travel.local` ทิ้งไว้เด็ดขาด** ระบบนับว่าใครที่มีอีเมลนี้คือผู้ดูแล
ถ้าบัญชีนี้หายไป ใครก็ตามที่รู้ apiKey (ซึ่งเปิดเผยอยู่ใน `firebase-config.js`) จะสมัครอีเมลนี้แล้วกลายเป็นผู้ดูแลได้
- ผู้ดูแลเปลี่ยนรหัสได้ในหน้า "เปลี่ยนรหัสผ่าน" ตามปกติ
- ถ้าผู้ดูแลลืมรหัส: ใน Firebase Console → Authentication → Users ให้ลบบัญชี `hwangning@travel.local` แล้ว **Add user อีเมลเดิมทันทีในหน้าเดียวกัน** อย่าเว้นช่วงไว้
  login ครั้งถัดไประบบจะสร้างโปรไฟล์ผู้ดูแลให้ใหม่ ผู้ดูแลยังเห็นทุกทริปเหมือนเดิม

คนที่รู้ apiKey สมัครบัญชี `<ชื่อ>@travel.local` เองได้ แต่จะไม่เห็นอะไรเลยจนกว่าผู้ดูแลจะสร้างโปรไฟล์ให้
ถ้าสร้างผู้ใช้แล้วขึ้นว่า "username นี้ยังมีบัญชีใน Firebase อยู่" ให้ลบบัญชีนั้นใน Firebase Console แล้วสร้างใหม่ในเว็บ

### ถ้าจะใช้ Firebase project เดียวกับ travel-shopping
ข้อมูลของระบบนี้อยู่ใต้ `planner/` จึงไม่ชนกับ `shop/` และ `config/` ของ travel-shopping
แต่ Rules ของฐานข้อมูลมีชุดเดียว ห้ามวางทับของเดิม ให้เอาก้อน `"planner": { ... }` จาก `database.rules.json`
ไปเพิ่มข้าง ๆ `"shop"` และ `"config"` ใน Rules เดิม แล้วค่อยกด Publish

## รูปภาพ
รูปจะถูกย่อในเบราว์เซอร์ก่อนบันทึก (รูปเต็มยาวสุด 1600px และรูปย่อ 360px) แล้วเก็บใน Realtime Database ใต้ `planner/photos` และ `planner/thumbs`
หน้ารายการโหลดเฉพาะรูปย่อ รูปเต็มโหลดตอนกดขยายเท่านั้น
Realtime Database แบบฟรีเก็บได้ 1 GB ใส่รูปได้ราว ๆ หลายพันรูป

## หมายเหตุ
ลิงก์ของแต่ละทริปเป็นแบบ `…/#trip=<id>` คนที่เป็นสมาชิกทริปนั้นเปิดได้โดยตรงหลังเข้าสู่ระบบ คนอื่นจะถูกพากลับไปหน้าปฏิทิน
รูปในทริปเปิดได้เฉพาะคนที่เข้าสู่ระบบแล้ว

## ทดสอบ (สำหรับคนแก้โค้ด)
- ฟังก์ชันใน `core.js`: `node --test "tests/*.test.js"`
- กฎฐานข้อมูล (ต้องมี Java): `cd tests/rules && npm install && npm test`
  แก้กฎที่ `tests/rules/gen_rules.py` แล้วสร้างไฟล์ใหม่ด้วย `python tests/rules/gen_rules.py database.rules.json`
  ใช้ Firebase จำลองบนเครื่อง ไม่แตะข้อมูลจริง
- ลองทั้งแอปกับ Firebase จำลอง: รัน `npx firebase emulators:start --only auth,database --project demo-trip` ใน `tests/rules`
  แล้วเปิดเว็บจาก `http://127.0.0.1:<port>/?emu=1` (โดยใช้ `firebase-config.js` ที่ projectId เป็น `demo-trip`)

## AI ช่วยจัดแพลน
ปุ่ม **"ให้ AI ช่วยจัดแพลน"** ในหน้าแผนรายวัน มี 2 โหมด

### โหมดคัดลอกคำสั่ง (ค่าเริ่มต้น · ฟรี · ไม่ต้องตั้งค่า)
1. กดปุ่ม → เลือกสไตล์ จังหวะ งบ และสิ่งที่อยากให้ AI ทำ → **สร้างคำสั่งสำหรับ AI**
2. กด **คัดลอกคำสั่ง** แล้วไปวางในแชท Claude / ChatGPT / Gemini (ใช้แบบฟรีได้)
3. คุยปรับกับ AI ได้ตามสบาย พอได้แบบที่ชอบ ให้ขอ "ส่ง JSON ฉบับล่าสุด" แล้วคัดลอกคำตอบกลับมาวางในเว็บ
4. กด **ดูตัวอย่างแพลน** → ติ๊กเลือกที่อยากได้ → **เพิ่มลงทริป**

### โหมดกดปุ่มเดียวจบ (ไม่บังคับ · ใช้ Claude API · มีค่าใช้จ่ายตามการใช้งาน)
ถ้าใส่ URL ใน `ai-config.js` ปุ่มจะเรียก Claude ให้ทันทีโดยไม่ต้องคัดลอกไปกลับ
เว็บเรียก Claude ตรง ๆ ไม่ได้ เพราะต้องซ่อน API key ไว้ จึงใช้ Cloudflare Worker (มีแบบใช้ฟรี) เป็นตัวกลาง
(บัญชีใหม่ใน Claude Console รับเครดิตทดลองฟรีครั้งเดียวได้ โดยยืนยันเบอร์มือถือ)

### 1. สร้าง API key ของ Claude
1. ไปที่ https://console.anthropic.com → สมัคร/ล็อกอิน
2. **Billing** → เติมเครดิต (จ่ายตามการใช้งาน) และแนะนำให้ตั้ง **Spend limit** รายเดือนไว้ กันค่าใช้จ่ายบานปลาย
3. **API Keys** → Create Key → คัดลอกเก็บไว้ (ขึ้นต้นด้วย `sk-ant-`)

### 2. สร้าง Cloudflare Worker
1. ไปที่ https://dash.cloudflare.com → สมัคร/ล็อกอิน
2. **Workers & Pages** → **Create** → **Create Worker** → ตั้งชื่อ เช่น `trip-ai` → **Deploy**
3. กด **Edit code** → ลบโค้ดเดิมทั้งหมด → วางเนื้อหาจากไฟล์ `ai-worker/worker.js` → **Deploy**
4. กลับไปหน้า Worker → **Settings** → **Variables and Secrets** → **Add** ทีละตัว:

| ชื่อ | ชนิด | ค่า |
|---|---|---|
| `ANTHROPIC_API_KEY` | Secret | API key จากขั้นตอนที่ 1 |
| `ACCESS_CODE` | Secret | รหัสที่คุณตั้งเอง (ยาว ๆ เดายาก) ใช้ใส่ในเว็บครั้งแรก กันคนอื่นแอบใช้ key ของคุณ |
| `ALLOWED_ORIGINS` | Text | `https://ningbenya.github.io` |
| `MODEL` | Text | ไม่บังคับ ค่าเริ่มต้น `claude-sonnet-5-5` (เปลี่ยนเป็น `claude-opus-5-5` ได้ แพงกว่าแต่ละเอียดกว่า) |

5. คัดลอก URL ของ Worker (ด้านบนของหน้า เช่น `https://trip-ai.yourname.workers.dev`)

### 3. ใส่ URL ในเว็บ
เปิดไฟล์ `ai-config.js` → ใส่ URL ใน `endpoint` → commit + push

ครั้งแรกที่กดปุ่ม AI เว็บจะถามรหัส `ACCESS_CODE` ใส่ครั้งเดียว เบราว์เซอร์จะจำไว้ (ถ้าใช้หลายเครื่องต้องใส่ทุกเครื่อง)

### ทดสอบบนเครื่องตัวเอง
ถ้าเปิดเว็บจาก `http://localhost:xxxx` ให้เพิ่ม URL นั้นใน `ALLOWED_ORIGINS` ด้วย คั่นด้วยจุลภาค
(เปิดไฟล์ index.html ตรง ๆ แบบ file:// จะใช้ AI ไม่ได้)

### หมายเหตุ
- จุดแวะที่ AI เพิ่มจะมีป้าย **"AI แนะนำ"** เวลาเปิด–ปิดและราคาเป็นค่าประมาณ ควรตรวจสอบอีกครั้งก่อนเดินทาง
- AI ไม่แก้หรือลบจุดแวะเดิม และจะเพิ่มเฉพาะรายการที่ติ๊กเลือกในหน้าตัวอย่าง
- ถ้าสงสัยว่ารหัสหลุด เปลี่ยน `ACCESS_CODE` ใน Worker ได้ทันที เว็บจะถามรหัสใหม่เอง
